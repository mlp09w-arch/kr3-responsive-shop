# Как показать КР №3 на защите

## Сначала объяснить основу

«Я взял HTML/CSS-магазин из КР №1 и создал отдельный проект kr3-responsive-shop. Bootstrap из КР №2 здесь нет. Задача — самостоятельно адаптировать раскладку через CSS и проверить доступность».

## 1. Где подключена адаптивность

В `head` каждой страницы:

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
<link rel="stylesheet" href="css/style.css" />
<link rel="stylesheet" href="css/responsive.css" />
```

Viewport связывает CSS-ширину с шириной устройства. Второй CSS подключён позже, чтобы его правила могли переопределять базовую раскладку.

## 2. Что такое Mobile First

Базовые правила описывают телефон, затем `min-width` расширяет раскладку:

```css
.product-grid {
  grid-template-columns: minmax(0, 1fr);
}

@media (min-width: 640px) {
  .product-grid {
    grid-template-columns: repeat(2, minmax(0, 1fr));
  }
}

@media (min-width: 1024px) {
  .product-grid {
    grid-template-columns: repeat(4, minmax(0, 1fr));
  }
}
```

Это фрагменты реальных правил из `responsive.css`; `display: grid` объявлен в общих стилях сеток. В каталоге отдельный модификатор сохраняет две колонки даже на desktop, потому что часть ширины занимает фильтр.

`minmax(0, 1fr)` разрешает колонке сжиматься меньше минимальной ширины её содержимого. Это помогает избежать переполнения из-за длинных текстов.

## 3. Где Flexbox, а где Grid

- Flexbox: `.site-nav__list`, `.product-card`, `.product-card__bottom`, `.order-form__actions`, `body`.
- Grid: `.hero__inner`, `.product-grid`, `.catalog`, `.order-layout`, `.order-form__row`, `.contacts`.

Flexbox удобен для одной последовательности элементов, Grid — для строк и колонок. На телефоне кнопки формы идут вертикально, а от 640 px — в ряд. Подвал прижимается вниз благодаря `body` с `min-height: 100dvh` и растущему `main`.

## 4. Как проверить адаптивность

В DevTools включить режим устройства и последовательно поставить 360, 430, 768, 1024 и 1440 px. Проверить меню, фото, каталог, поля формы, характеристики и подвал. На телефоне вся страница не должна прокручиваться вбок. У таблицы на некоторых ширинах допускается своя локальная прокрутка.

## 5. Что делают srcset, sizes и picture

- `srcset` перечисляет реальные файлы с ширинами 360/640/900 px.
- `sizes` сообщает браузеру предполагаемую ширину фото в макете.
- Браузер выбирает файл с учётом доступной ширины, DPR и кэша.
- `<picture>` на главной предлагает AVIF, а `<img>` содержит WebP-fallback.
- `width`/`height` резервируют пропорции; CSS `max-width: 100%` и `height: auto` не дают фото выйти за контейнер.
- `loading="lazy"` откладывает загрузку карточек ниже первого экрана.

Открыть Network → Img и перезагрузить страницу на выбранной ширине. При проверке переключать устройства с отключённым кэшем; иначе браузер может оставить уже загруженный крупный файл.

## 6. Как устроены меню, фильтры и окно доставки без JS

Мобильное меню использует `popover` и кнопку `popovertarget`, область фильтров — `details` и `summary`, окно доставки — `dialog` и `commandfor`/`command="show-modal"`. Это встроенные HTML-возможности современного браузера. Собственных скриптов нет.

У фильтров реализован только макет: флажки не меняют каталог. Не нужно говорить, что здесь есть JavaScript-фильтрация.

Открыть меню клавиатурой, пройти Tab, нажать Escape. Затем открыть доставку, пройти Tab, закрыть Escape и показать возврат фокуса к кнопке открытия.

## 7. Как адаптирована таблица

На телефоне виден `<dl>` с парами «название — значение», а от 640 px — настоящая таблица. Скрытый вариант выключен через `display: none` и не читается второй раз программой экранного доступа. На desktop таблица имеет `caption`, `th`, `scope` и обёртку с `overflow-x: auto`.

## 8. Что исправлено в доступности

Показать первый Tab и skip-link, видимый фокус, `label for` и соответствующий `id`, `alt`, `aria-current="page"`, контраст кнопок и тексты оценок отзывов. ARIA не заменяет обычные HTML-элементы.

Заголовки: один `h1` обозначает страницу, `h2` — разделы, `h3` — карточки внутри разделов.

## 9. Как проверяется форма

`required`, `type="email"`, `minlength`, `maxlength` и `pattern` проверяет сам браузер. `type="tel"` обозначает телефон, но сам формат не проверяет — для этого есть `pattern`.

Нажать «Проверить заявку» с пустыми полями, затем заполнить тестовыми данными. `method="dialog"` закрывает открытый немодальный блок формы после успешной проверки, а CSS показывает результат. Реальные данные не отправляются и не появляются в URL. Отдельного backend нет.

## 10. Что проверил Lighthouse

Открыть любой `lighthouse/*.report.html`. В категории Accessibility все пять страниц получили 100/100. Это автоматические проверки разметки, доступных имён, подписей и контраста. Они не подтверждают полную доступность и не оценивают удобство сценария, поэтому отдельно проверены клавиатура и разные ширины.

## 11. Что добавлено самостоятельно

Мобильное меню без скриптов, сворачиваемый фильтр, мобильные карточки характеристик, AVIF и варианты WebP, нативный доступный диалог, форма обратной связи, подробные результаты ручных и автоматических проверок.
